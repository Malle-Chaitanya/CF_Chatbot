================================================================================
                        AUTHENTICATION FLOW
================================================================================

User Not Logged In:
  GET /
    ↓ Redirects
  GET /login
    ↓ User clicks "Login with Microsoft"
  Redirects to Microsoft OAuth
    ↓ User enters credentials
  Microsoft redirects back with code
    ↓ Backend exchanges code for token
  Token stored in localStorage
    ↓ Redirects to /chat/new
  User sees chat interface

User Logged In:
  GET / → Redirect to /chat/new
    ↓
  Check localStorage for user
    ↓
  Verify token with Microsoft Graph API
    ↓
  Check email ends with @cloudfuze.com
    ↓
  Render chat UI
    ↓
  Ready to chat!

================================================================================
                    SESSION ID FORMAT DETECTION
================================================================================

Session ID Format:

Type 1: cf.conversation.20251208.abc123
  ├─ Prefix: "cf.conversation."
  ├─ Date: 20251208 (YYYYMMDD)
  ├─ Random: abc123 (random string)
  ├─ Generated: On first message
  ├─ Storage: localStorage
  ├─ Route: /chat/cf.conversation...
  └─ Access: Read/Write

Type 2: user_chat_alice123
  ├─ Prefix: "user_chat_"
  ├─ UserId: alice123 (user identifier)
  ├─ Generated: By backend for other users
  ├─ Storage: NOT saved (temporary)
  ├─ Route: /chat/others/user_chat_...
  └─ Access: Read-only


Detection Logic in Code:

  if (sessionId.startsWith('user_chat_')) {
    // This is Others Chat
    loadOthersSession(sessionId)  // Fetch from backend
    setReadOnly(true)             // Disable input
  } else {
    // This is Own Chat
    loadSession(sessionId)        // Load from localStorage
    setReadOnly(false)            // Enable input
  }

================================================================================
                      MESSAGE LIFECYCLE
================================================================================

User sends message at /chat/new:

Step 1: Input Phase
  ├─ User types message in input field
  ├─ Character count tracked
  ├─ Length validation (max 20000 chars)
  └─ Ready for submit

Step 2: Send Phase
  ├─ User clicks send button
  ├─ Button disabled (opacity 0.5)
  ├─ Show "Generating response..." tooltip
  └─ API request sent

Step 3: Request Phase
  ├─ POST /api/chat/send
  ├─ Headers: Authorization Bearer token
  ├─ Body: { message, session_id: null }
  └─ Wait for response

Step 4: Stream Phase
  ├─ Server sends chunks
  ├─ Each chunk contains message text
  ├─ No sessionId yet (created on completion)
  └─ Streaming until "done" message

Step 5: Render Phase
  ├─ Each chunk received
  ├─ Markdown processing (marked.js)
  ├─ HTML rendering
  ├─ Auto-scroll to bottom
  └─ No DOM updates (await completion)

Step 6: Complete Phase
  ├─ "done" event received
  ├─ Full response message set
  ├─ Recommended questions loaded
  ├─ Session ID generated
  ├─ Save to localStorage
  ├─ Send to backend for persistence
  └─ Mark as not generating

Step 7: Navigate Phase (100ms delay)
  ├─ Extract sessionId from current state
  ├─ Call router.push(`/chat/${sessionId}`)
  ├─ URL updates in browser
  ├─ New route loads
  ├─ Page re-renders
  └─ Session appears in sidebar

Step 8: Final Phase
  ├─ User now on /chat/[sessionId]
  ├─ Can send more messages
  ├─ Can click other sessions
  ├─ Session persisted
  └─ Can refresh page without losing chat


================================================================================
                          SUMMARY
================================================================================

Routes Work Together Like This:

/ → /chat/new → (on first message) → /chat/[sessionId] → user continues

Each route handles:
  - Authentication & authorization
  - Session management
  - UI rendering
  - Error handling

Session detection happens automatically:
  - Own sessions load from localStorage (fast)
  - Others sessions load from backend (api)
  - Read-only mode enforced automatically

Navigation is automatic:
  - After first message → URL updates with sessionId
  - User can navigate between sessions in sidebar
  - Back button goes back in browser history

Data is secure:
  - Others chats not saved locally
  - Token verified on every route
  - CloudFuze domain enforced
  - Read-only mode for others

Everything optimized for production:
  - localStorage for fast loads
  - Backend for others chats
  - Streaming for real-time responses
  - Back/forward optimization
